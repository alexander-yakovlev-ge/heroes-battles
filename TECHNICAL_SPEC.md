# Техническое задание: Heroes Battles

## 1. Обзор проекта

Пошаговая тактическая PvP-игра в браузере и мобильных приложениях (iOS, Android). Механика боёв вдохновлена heroeswm.ru (Heroes of War and Money). Рынок — глобальный; языки на старте — английский и русский.

**«Без сервера»** означает: нет собственных серверов и VM. Вся серверная логика — бессерверная, на Firebase (Firestore, Cloud Functions, Auth, Storage). Cloud Functions требуют тарифа Blaze (pay-as-you-go).

Ключевые принципы:
- **Донат не даёт боевого преимущества.**
- **Клиенту не доверяем**: весь PvP-state меняет только Cloud Functions; случайность генерируется на сервере.
- **Единая игровая логика**: пакет `game-core` исполняется и на клиенте (бой с ботом, предпросмотр ходов), и в Cloud Functions (каноничный PvP-state).
- **Баланс по данным**: стартовые характеристики подбираются логически, затем корректируются по статистике боёв (§13).

Пробная версия разрабатывается ИИ (код и графика); владелец продукта проверяет и утверждает результат. В дальнейшем возможен найм художника.

## 3. Firebase — структура данных

**Источник правды для боя — Firestore.** Realtime Database используется только для presence (онлайн/офлайн) и командного чата.

### 3.1 Firestore Collections

```

  displayName, createdAt, lastSeen

  pushToken?: string

  banned: boolean                   // пишет только админ через CF (§7.9)

/users/{uid}/blocked/{otherUid}     — персональный чёрный список, пишет владелец (§7.9)

  startingRace: RaceId              // выбирается игроком при создании героя
  statHistory: StatId[]             // порядок распределения очков статов (index = уровень-1)
  raceSkillHistory: RaceId[]        // порядок распределения очков навыков рас
  pendingStatPoints, pendingRaceSkillPoints
  lastFreeRespecSeason: number | null

  stats: { attack, defense, power, knowledge }

/armies/{uid}/presets/{presetId}    — пишет владелец

/ratings/{uid}                      — пишет только CF; лидерборды = запросы по этой коллекции
  mode1v1: { rating, games, wins, losses, draws }
  mode2v2: { rating, games, wins, losses, draws }
  mode3v3: { rating, games, wins, losses, draws }

/parties/{partyId}                  — пишет только CF (§7.4)
  leader: uid
  members: uid[]                    // 2–3
  mode: '2v2' | '3v3'
  inviteCode: string
  status: 'forming' | 'queued' | 'in_battle'

/rooms/{roomId}                     — приватные бои по коду, пишет только CF (§7.5)
  code: string
  host: uid
  mode, players: uid[]
  battleId: string | null

/matchmaking/{ticketId}             — тикет игрока или пати
  queue: 'ranked' | 'casual'        // casual — для гостей (§7.6)
  mode: '1v1' | '2v2' | '3v3'
  uids: uid[]                       // один игрок или вся пати
  partyId: string | null
  presetIds: Record<uid, presetId>
  joinedAt
  allowBots: boolean                // согласие на добор команды ботами (§7.8)
  battleId: string | null           // CF проставляет при нахождении матча
  // level и rating в тикет не кладутся — CF читает их сам

/battles/{battleId}                 — читают участники, пишет только CF

  mode, queue, isRanked
  balanceVersion: string            // версия игровых данных game-core
  teams: { red: string[], blue: string[] }   // uid игроков или id ботов
  bots: Record<botId, { difficulty: 'normal' }>  // боты-заменители (§7.8)
  battleLevel: number               // уровень, к которому приведены все герои (§8)
  heroes: Record<uid, BattleHero>   // снимок героев ПОСЛЕ балансировки
  grid: { width, height, obstacles: [x, y][] }
  units: UnitState[]
  queue: unitId[]                   // очередь хода текущего раунда
  activeUnitId: string
  round: number
  turnDeadline: Timestamp
  seq: number                       // номер последнего применённого действия
  winner: 'red' | 'blue' | 'draw' | null
  endReason: 'elimination' | 'surrender' | 'timeout' | 'round_limit' | null
  createdAt, finishedAt

/battles/{battleId}/events/{seq}    — лог боя (UI, реплеи, аналитика), пишет CF
/battles/{battleId}/private/server  — rngState, читать не может никто, кроме CF

/battleStats/{battleId}             — пишет CF по окончании боя, экспортируется в BigQuery (§13)

/entitlements/{uid}                 — пишет только CF (вебхуки платежей)
  skins: string[], xpBoostBattles: number, presetSlots: number,

/config/season                      — пишет только админ/CF
  current: number, startsAt, endsAt  // сезон = 8 недель

/reports/{reportId}                 — создаёт CF по жалобе игрока (§7.9)
  reporter: uid, target: uid, battleId?, reason, comment?
```

Лог вынесен в подколлекцию, чтобы документ боя не упирался в лимит 1 МБ.

## 4. Игровые сущности

### 4.1 Расы и юниты

8 рас × 7 уровней (tier). На каждом уровне — **базовый юнит и альтернативный** (например, Skeleton — ближний бой, Skeleton Archer — стрелок): итого 112 юнитов. Альтернативный юнит — «sidegrade»: другая роль при сопоставимой силе и весе, а не улучшенная версия. Крупные (2×2) — в основном юниты 5–7 уровня, отдельные — 4-го.

Имена — только общеупотребительные фэнтези/мифологические понятия, без отличительных названий из heroeswm.ru и Heroes of Might and Magic. Внешний вид юнитов — собственный (§10.1).

Состав юнитов утверждён владельцем продукта; числовые характеристики подбираются по правилам ниже.

Стартовые характеристики подбираются по правилам, затем корректируются по статистике (§13):
- «сила» юнита (эффективный урон × эффективное HP с учётом скорости, инициативы и способностей) растёт с уровнем примерно в 1.8–2.2 раза за уровень;
- `weight` пропорционален «силе», чтобы армии одного веса были сопоставимы;
- каждая раса имеет выраженную роль (например, некроманты — живучесть, демоны — урон, эльфы — стрелки) и не имеет слабых уровней по всем параметрам сразу;
- базовый и альтернативный юнит одного уровня отличаются ролью (ближний бой / стрелок, скорость / живучесть, способность), «сила» в пределах ±10%.

### 4.2 Открытие юнитов

Уровни юнитов открываются **уровнем героя** (для всех рас сразу), альтернативные юниты — **навыком конкретной расы**:

| Уровень юнита | Базовый: уровень героя | Альтернативный: навык расы |
|---|---|---|
| 1–2 | 1 | ≥ 4 |
| 3 | 3 | ≥ 4 |
| 4 | 6 | ≥ 5 |
| 5 | 10 | ≥ 6 |
| 6 | 14 | ≥ 7 |
| 7 | 18 | ≥ 8 |

Альтернативный юнит доступен, только если открыт и соответствующий уровень юнита. Доступность всегда вычисляется из уровня и навыков героя (в бою — после балансировки, §8) и нигде не хранится.

Что даёт прокачка (без преимущества в конкретном бою, §8):
- новые уровни юнитов и альтернативные юниты;
- новые заклинания (§5.7);
- больший лимит веса — более глубокие стаки (§6.1);
- снижение стоимости юнитов прокачанных рас — больше вариантов состава армии.

### 4.3 Параметры юнита

```typescript
interface UnitTemplate {
  id: string
  raceId: RaceId
  tier: 1 | 2 | 3 | 4 | 5 | 6 | 7

}

  id: string            // уникален в бою
  templateId: string
  owner: string         // uid
  team: 'red' | 'blue'
  count: number         // живых существ
  initialCount: number
  topHp: number         // HP верхнего существа стака
  x: number; y: number  // для крупных — левая верхняя клетка
  shotsLeft?: number
  retaliatedThisRound: boolean
  waitedThisRound: boolean
  defending: boolean
  effects: { id: EffectId; roundsLeft: number; value?: number }[]

```

### 4.4 Герой

У героя нет HP — он не находится на поле и не может быть атакован.

```typescript
interface Hero {
  uid: string
  level: number             // 1–30
  experience: number
  startingRace: RaceId
  stats: {
    attack: number          // бонус к атаке всех юнитов
    defense: number         // бонус к защите всех юнитов
    power: number           // сила заклинаний
    knowledge: number       // максимум маны = knowledge * 10
  }
  raceSkills: Record<RaceId, number>  // 0–9, влияет на вес юнитов и доступ к заклинаниям расы
  statHistory: StatId[]
  raceSkillHistory: RaceId[]
}

// Снимок героя в бою — после балансировки (§8)
interface BattleHero {
  uid: string
  realLevel: number
  stats: Hero['stats']
  raceSkills: Hero['raceSkills']
  spells: SpellId[]         // доступные на battleLevel с учётом навыков рас (§5.7)
  mana: number
  maxMana: number
  castThisRound: boolean
}
```

## 5. Система боя

### 5.1 Поле

Размер поля и число стаков зависят от режима (пересматриваются по итогам тестов):

| Режим | Поле | Стаков на героя | Зона расстановки |
|---|---|---|---|
| 1v1 | 12 × 8 | до 7 | 2 крайних столбца |
| 2v2 | 14 × 10 | до 5 | 2 крайних столбца |
| 3v3 | 16 × 12 | до 4 | 2 крайних столбца |

- Препятствия: 10–15% клеток, только вне зон расстановки.
- Расстановка **зеркально симметрична** относительно вертикальной оси — ни одна сторона не получает преимущества.
- После генерации — проверка связности (BFS с учётом footprint 2×2): из зоны расстановки каждой стороны достижима зона противника и для обычных, и для крупных юнитов; иначе перегенерация.
- Генерация — на сервере из seed боя.
- Красная команда стартует слева, синяя — справа. В командных режимах зона расстановки делится между героями команды по вертикали.
- Начальная расстановка — автоматическая по порядку слотов пресета (крупные юниты ставятся первыми).

### 5.2 Крупные юниты (2×2)

- Занимают 4 клетки; позиция — левая верхняя клетка.
- Перемещение: путь ищется для footprint 2×2 — все 4 клетки должны быть свободны на каждом шаге (летающие проверяют только конечную позицию).
- Соседство для ближнего боя: любая клетка, граничащая (в 8 направлениях) с любой из 4 клеток юнита.
- Дальность стрельбы и заклинаний считается до ближайшей клетки юнита.
- `area_attack`, Fireball и прочие площадные эффекты задевают крупного юнита один раз, если покрывают хотя бы одну его клетку.

### 5.3 Порядок хода

1. В начале раунда все живые юниты сортируются по `initiative` (с учётом эффектов Haste/Slow) по убыванию. При равенстве: выше `speed` → первым; затем — порядок, определённый жребием в начале боя (из seed), чередуя команды.
2. Активный юнит выполняет одно действие:
   - **Move** — переместиться (без атаки);
   - **Attack** — атака с места или Move + Attack (ближний бой);
   - **Shoot** — выстрел (стрелки);
   - **Wait** — переместиться в конец очереди текущего раунда (не чаще 1 раза за раунд);
   - **Defend** — +30% к защите до следующего своего хода.
3. **Заклинание**: герой может один раз за раунд произнести заклинание в ход **любого своего** юнита; это не тратит действие юнита.
4. После хода всех юнитов — новый раунд, флаги `retaliatedThisRound` / `waitedThisRound` / `castThisRound` сбрасываются, длительность эффектов уменьшается.
5. Конец боя:
   - все юниты одной команды мертвы;
   - сдача (в командных режимах — сдача игрока снимает его юнитов; команда проигрывает, когда юнитов не осталось);
   - технический проигрыш по тайм-аутам (§5.4);
   - лимит 30 раундов: сравнивается доля оставшейся армии каждой команды `Σ(count × weight) / Σ(initialCount × weight)`; при разнице < 5 п.п. — ничья, иначе победа большей доли.

### 5.4 Таймер хода и отключения

Бои только **синхронные** (все игроки в игре одновременно); асинхронного режима нет.

- На каждое действие юнита — **30 секунд** + общий резерв **90 секунд** на бой на игрока (тратится, когда основной таймер истёк).
- Истёк таймер и резерв → сервер (`onTurnTimeout`) выполняет за юнита **Defend**.
- 3 тайм-аута подряд у одного игрока → его юниты снимаются с боя (= сдача).
- Потеря соединения не останавливает бой — работают те же таймеры. После переподключения клиент подписывается на `/battles/{id}` и продолжает.
- Presence (RTDB) используется только для UI («противник офлайн»).

### 5.5 Формула урона

```
atk  = unit.attack + hero.attack
def  = target.defense + targetHero.defense
       (× 1.3, если target.defending)
diff = atk - def

attackMultiplier =
  diff >= 0 ? min(1 + 0.05 * diff, 3.0)
            : max(1 / (1 + 0.05 * -diff), 0.3)

base   = sum(random(damageMin, damageMax)) по min(count, 10) существам,
         × count / min(count, 10)          // для больших стаков — масштабирование
damage = max(1, floor(base * attackMultiplier * modifiers))
```

`modifiers` — произведение применимых множителей:
| Множитель | Значение |
|---|---|
| Стрелок стреляет, находясь вплотную к врагу | 0.5 |
| Стрелок стреляет дальше `range` | 0.5 |
| Ответный удар | 1.0 |
| Эффекты заклинаний/способностей | по описанию |

Применение урона: снимается с `topHp`, затем целыми существами; `count` уменьшается.

**Случайность**: детерминированный PRNG (например, xoshiro128**) из `game-core`. В PvP состояние генератора хранится в `/battles/{id}/private/server` и недоступно клиентам, поэтому клиент не может предсказать броски. В бою с ботом seed локальный.

### 5.6 Типы атак и способности

- **Ближний бой** — по соседней клетке (8 направлений). Цель, если выжила и ещё не отвечала в этом раунде, наносит **ответный удар** (1 раз за раунд, без способности `no_retaliation` у атакующего).
- **Дальний бой** — по любой клетке поля; дальше `range` — штраф 50%. Расходует 1 выстрел. Ответного удара нет. Без выстрелов или вплотную к врагу стрелок может атаковать в ближнем бою.
- **Летящие** — игнорируют препятствия и юнитов при движении (дистанция — по прямой, Chebyshev).
- **Движение** — по 8 направлениям, путь ищется A*, стоимость шага 1.

| Способность | Описание |
|---|---|
| `double_attack` | Атакует дважды (ответный удар — после первой атаки) |
| `no_retaliation` | Цель не наносит ответный удар |
| `life_drain` | 50% нанесённого урона восстанавливает HP стака, в том числе поднимает погибших существ (не выше `initialCount`) |
| `area_attack` | Урон по цели и всем юнитам в соседних клетках (3×3), включая своих |
| `poison` | Яд: в начале хода цели урон `20%` от урона отравившего удара, 3 раунда; не действует на нежить и `poison_immune` |
| `fire_breath` | Урон по цели и клетке за ней |
| `unlimited_retaliation` | Отвечает на все атаки ближнего боя, а не 1 раз за раунд |
| `charge` | +5% урона за каждую клетку, пройденную перед атакой (макс. +50%) |
| `entangle` | При ударе цель не может перемещаться до конца своего следующего хода |
| `petrify` | Шанс 20% при ударе: цель пропускает следующий ход |
| `stun` | Шанс 20% при ударе: цель теряет 50% инициативы на 1 раунд |
| `regeneration` | В начале хода восстанавливает HP верхнего существа стака |
| `rebirth` | Раз в бой при гибели стака: возрождает 30% от начальной численности |
| `incorporeal` | Шанс 30% избежать урона от атаки ближнего боя |
| `magic_resist` | −50% урона и длительности вражеских заклинаний |
| `aura_magic_resist` | `magic_resist` для союзников в соседних клетках |
| `aura_defense` | +20% защиты союзникам в соседних клетках |
| `fire_aura` | В начале хода наносит соседним врагам `25%` среднего урона стака (кроме `fire_immune`) |
| `mana_drain` | При атаке сжигает ману героя противника: `max(1, round(вес стака / 20))` |
| `caster` | Раз в бой вместо атаки применяет указанное заклинание; сила = `max(1, round(вес стака / 10))` |
| `chain_attack` | Атака перескакивает на 2 ближайших врагов с уроном 50% и 25% |
| `return_strike` | После атаки возвращается на исходную клетку |
| `teleport` | Перемещается в любую свободную клетку в пределах `speed` без учёта пути |
| `ignore_range_penalty` | Нет штрафа за дальность стрельбы |
| `undead` | Иммунитет к яду и Blind; цель для Raise Dead, не цель для Resurrection |
| `aura_dread` | Соседние враги −1 к инициативе |
| `no_melee_penalty` | Нет штрафа при стрельбе вплотную к врагу |
| `all_around_attack` | Ближний бой: урон и всем остальным соседним врагам |
| `deadly_strike` | Шанс 20% нанести двойной урон |
| `initiative_drain` | При ударе −2 инициативы цели на 2 раунда |
| `curse_on_hit` | При ударе −3 атаки цели на 2 раунда |
| `dispel_on_hit` | При ударе снимает с цели положительные эффекты |
| `fire_immune` | Не получает урон от огня (`fire_breath`, `fire_aura`, огненные заклинания) |
| `poison_immune` | Иммунитет к яду |
| `blind_immune` | Иммунитет к Blind |
| `spell_immune` | Не может быть целью заклинаний и не получает от них урон |

### 5.7 Заклинания

- Максимум маны = `knowledge × 10`; в начале боя мана полная, в бою **не восстанавливается**.
- Сила эффекта масштабируется от `power`.
- Заклинания делятся на **круги** и **школы**: общая школа доступна всем, школа расы — только при достаточном навыке этой расы. Так как навыки можно качать в нескольких расах параллельно, герою могут быть доступны заклинания нескольких школ.
- Заклинание доступно, если выполнены оба условия (проверяются для **уровня боя** `battleLevel` и навыков после балансировки, §8):

| Круг | Уровень героя | Навык расы (для школы расы) |
|---|---|---|
| 1 | 1 | — |
| 2 | 5 | ≥ 2 |
| 3 | 10 | ≥ 4 |
| 4 | 15 | ≥ 6 |
| 5 | 20 | ≥ 8 |

Стартовый набор (черновик, подлежит утверждению и балансировке):

| Заклинание | Школа | Круг | Мана | Эффект |
|---|---|---|---|---|
| Lightning Bolt | общая | 1 | 8 | Урон `10 + power × 6` по стаку |
| Cure | общая | 1 | 6 | Лечит `10 + power × 5` HP стаку, снимает дебафы |
| Haste | общая | 1 | 6 | +3 инициативы, 3 раунда |
| Slow | общая | 2 | 8 | −3 инициативы и −1 скорость, 3 раунда |

| Resurrection | knight | 4 | 20 | Поднимает `power × 15` HP погибших существ стака (не выше `initialCount`) |
| Curse | necro | 2 | 8 | −`2 + power/3` к атаке стака врага, 3 раунда |
| Raise Dead | necro | 3 | 16 | Поднимает `power × 20` HP погибших существ стака нежити |

## 6. Система армии (Замок)

### 6.1 Вес армии

```
maxWeight(level) = 100 + level * 10

unitCost(unit, raceSkills) = unit.weight * weightMultiplier(raceSkills[unit.raceId])

weightMultiplier(skill):
  0 → 2.00   1 → 1.60   2 → 1.30   3 → 1.00   4 → 0.90
  5 → 0.80   6 → 0.70   7 → 0.63   8 → 0.56   9 → 0.50

armyWeight = Σ unitCost(slot.unit) * slot.count
```

### 6.2 Формирование армии

- Игрок выбирает юнитов из любых рас — только открытых (§4.2).
- `armyWeight ≤ maxWeight(hero.level)`; минимум 1 юнит.
- Число стаков ограничено режимом (§5.1). Для режимов 2v2 / 3v3 используются первые 5 / 4 слота пресета.
- Пресеты сохраняются между боями (1 бесплатный, дополнительные — покупка, §12.3).
- Перед боем сервер **всегда** пересчитывает вес по шаблонам юнитов и балансированному герою (§8); клиентскому весу не доверяем.

### 6.3 Экран Замка

- Список рас → список юнитов расы с иконкой и характеристиками.
- Слайдер или ввод количества юнитов.
- Индикатор веса (текущий / максимальный).
- Кнопки «Сохранить пресет» и «В бой».

## 7. PvP и матчмейкинг

### 7.1 Режимы

| Режим | Команды | Особенности |
|---|---|---|
| 1v1 | 1 герой vs 1 | Классическая дуэль |
| 2v2 | 2 героя vs 2 | Командный чат, пати |
| 3v3 | 3 героя vs 3 | Командный чат, пати |

В командных режимах общая очередь инициативы на всех юнитов; ход делает владелец активного юнита. Заклинания каждый герой кастует сам (1 раз за раунд).

### 7.2 Рейтинг (Elo)

- **Раздельные рейтинги** для 1v1, 2v2 и 3v3; отдельный лидерборд на каждый режим.
- Базовый рейтинг: 1000.
- K-фактор: 32 (первые 10 боёв в режиме), 16 (после).
- Командный бой: рейтинг команды = среднее рейтингов игроков; ожидаемый результат считается по рейтингам команд; каждый игрок получает изменение, рассчитанное от своего K.
- Бои с ботом, casual-бои и приватные бои не рейтинговые.

### 7.3 Условия подбора

Матч возможен, только если выполнены **оба** условия:
1. **Разница уровней**: `maxLevel − minLevel ≤ MAX_LEVEL_GAP = 3` среди всех участников боя. Ограничение жёсткое и **не расширяется** со временем.
2. **Рейтинг**: окно ±100 вокруг рейтинга тикета (для пати — среднего), расширяется на +50 каждые 30 секунд ожидания.

Тайм-аут поиска — 3 минуты → клиент предлагает бой с ботом. При низком онлайне на старте основную нагрузку берут на себя боты (§9).

### 7.4 Пати (2v2, 3v3)

- Лидер создаёт пати и делится кодом приглашения / ссылкой; участники вступают по коду.
- Размер пати: от 2 до размера команды режима (в 3v3 допустима пати из 2 + 1 одиночный игрок).
- Ограничение уровней (§7.3) действует и внутри пати: пати с разницей уровней > 3 в рейтинговую очередь не допускается (может играть в приватных боях, §7.5).
- В очередь пати ставит лидер; один тикет на всю пати.
- При подборе приоритет — пати против пати сопоставимого размера; если за 60 секунд таких нет — допускается против одиночных игроков.

### 7.5 Приватные бои

- Игрок создаёт комнату (`createRoom`) и передаёт код; соперники входят по коду.
- Любой режим, любые уровни (балансировка §8 применяется, ограничение разницы уровней — нет).
- Не рейтинговые, не дают опыта и прогресса Battle Pass.

### 7.6 Гости

- Вход без регистрации — анонимная аутентификация Firebase.
- Гостю доступны: бой с ботом, **casual-очередь 1v1** против других гостей, приватные бои по коду.
- Гостевой герой: фиксированный уровень 5, стартовая раса на выбор, навык стартовой расы 3; можно собирать армию.
- Гостевые бои не дают опыта, рейтинга и прогресса Battle Pass; покупки гостям недоступны.
- Гость может в любой момент привязать аккаунт (email / Google / Apple) — тогда создаётся обычный герой уровня 1.
- Неактивные 30 дней гостевые аккаунты удаляются (`cleanupGuests`).

### 7.7 Флоу подбора

```
Клиент → enqueue (callable) → CF создаёт /matchmaking/{ticketId}
matchmakingTick (на создание тикета и раз в минуту):
  → в транзакции выбирает совместимые тикеты (очередь, режим, §7.3, §7.4, чёрные списки §7.9),
    проверяя battleId == null
  → если команда 2v2/3v3 не набирается, а все её участники дали согласие — добирает ботов (§7.8)
  → проверяет и балансирует армии (§8), создаёт /battles/{id}
  → проставляет battleId всем участвующим тикетам
Клиент слушает свой тикет; при появлении battleId → переход в бой.
Тикеты старше 3 минут и отработанные тикеты удаляет matchmakingTick.
```

Транзакция исключает ситуацию, когда два параллельных вызова функции забирают одного игрока в два боя.

Забаненный игрок (`users.banned`) в очередь, пати и комнаты не допускается — проверяется в `enqueue`, `joinParty`, `joinRoom`.

### 7.8 Добор команды ботами (2v2, 3v3)

- Если тикет в командном режиме ждёт дольше 90 секунд, клиент предлагает: «Добрать команду ботами?». Ответ сохраняется в тикете (`allowBots`); его можно отозвать до начала боя.
- Матчмейкер формирует бой с ботами, только если **все** игроки-люди будущего боя дали согласие и людей в бою не меньше двух (иначе это обычный бой с ботом, §9).
- Ботов может быть в любой команде; людей в командах должно быть поровну или с перевесом не больше одного.
- Такой бой — **тренировочный**: не даёт рейтинга, опыта и прогресса Battle Pass.
- Бот-заменитель получает героя уровня `battleLevel` и армию максимального веса для этого уровня; играет сложностью Normal.
- Ходы ботов вычисляет Cloud Function (`runBotTurn`) с тем же `game-core` — клиентам ходы ботов не доверяются.

### 7.9 Жалобы, чёрный список, бан

- **Жалоба**: кнопка в бою, в чате и в профиле игрока → `reportPlayer`. CF сохраняет жалобу в `/reports` вместе со снимком сообщений цели из чата боя. Автоматических санкций нет; фильтра лексики нет.
- **Персональный чёрный список**: игрок добавляет другого в `/users/{uid}/blocked`. Эффекты:
  - матчмейкер не сводит их ни соперниками, ни союзниками;
  - сообщения заблокированного в чате скрываются;
  - заблокированный не может пригласить в пати и не видит комнаты по ссылке от этого игрока.
- **Бан**: только вручную, администратором (владельцем продукта) через `setBan` по итогам рассмотрения жалоб. На старте жалобы просматриваются в консоли Firebase; админ-панель — позже по необходимости.

## 8. Балансировка уровней

Цель: купленный или нафармленный опыт не даёт преимущества в бою.

1. **Ограничение разницы**: рейтинговый матчмейкинг сводит только героев с разницей уровней ≤ 3 (§7.3).
2. **Уровень боя**: `battleLevel = min(level всех участников)`. Все герои выше этого уровня приводятся к нему — **балансировка по более слабому**.
3. **Приведение героя к уровню L** — детерминированно, через историю распределения очков:
   - статы: базовые значения + первые `L − 1` записей из `statHistory`;
   - навыки рас: стартовый навык + первые `floor(L / 3)` записей из `raceSkillHistory`;
   - заклинания: по кругам, открытым на уровне L, с учётом навыков рас после приведения (§5.7);
   - лимит веса армии: `maxWeight(L)`.
4. **Автоматическое урезание армии**, если её вес (пересчитанный по навыкам уровня L) больше `maxWeight(L)`:
   - `k = maxWeight(L) / armyWeight`; каждый стак: `count = max(1, floor(count × k))`;
   - если вес всё ещё превышен — по 1 существу снимается со стака с наибольшим `unitCost`, пока вес не уложится.
5. **Замена недоступных юнитов**: если в армии есть юнит, не открытый на уровне L или при навыках после приведения (§4.2):
   - альтернативный юнит заменяется базовым того же уровня и расы;
   - юнит неоткрытого уровня заменяется базовым юнитом наивысшего открытого уровня той же расы;
   - число существ пересчитывается так, чтобы вес стака сохранился (`floor`, минимум 1).
   Замена выполняется до урезания по весу (п. 4 применяется к уже заменённой армии).
6. **UI**: в лобби и в бою явно показывается «Бой на уровне L» и для приведённых героев — «Выравнивание уровня: 18 → 16», а также итоговый состав армии после замены и урезания.
7. При разнице уровней ≤ 3 урезание затрагивает не более ~30 единиц веса — состав почти не меняется.

```typescript
function balanceHero(hero: Hero, battleLevel: number): BattleHero
function balanceArmy(slots: ArmySlot[], hero: BattleHero, battleLevel: number): ArmySlot[]
```

## 9. Боты

- Реализованы в `game-core/ai/`. В бою с ботом исполняются на клиенте; в PvP-бою с добором ботами (§7.8) — в Cloud Functions.
- На старте компенсируют низкий онлайн: бой с ботом доступен сразу из меню и предлагается по тайм-ауту поиска.
- **Не влияют** на рейтинг, опыт, Battle Pass и любую прогрессию; бой с ботом полностью локальный, Firebase не используется.
- Бот получает армию того же веса, что и игрок (случайный состав из пресетов-шаблонов), и героя того же уровня.
- Сложности:
  - **Easy**: случайное допустимое действие.
  - **Normal**: жадный — максимум ожидаемого урона за ход с учётом ответного удара.
  - **Hard**: expectimax на 2 хода вперёд (по средним значениям урона) с лимитом 500 мс; при необходимости позже — MCTS.
- ИИ выполняется в Web Worker / отдельном JS-потоке, чтобы не блокировать UI.

### 10.1 Графика

### 10.2 Локализация

- Языки на старте: **английский** (по умолчанию) и **русский**; архитектура рассчитана на добавление новых.
- Все строки — в `packages/i18n`; игровые данные содержат только ключи (`nameKey`, `descriptionKey`).
- Язык определяется по системе (expo-localization) и меняется в настройках.
- Никнеймы и чат не переводятся и не фильтруются; модерация — через жалобы (§7.9).

## 11. Прогрессия героя

### 11.1 Уровни и очки

- Опыт начисляется **только за рейтинговые PvP-бои**.
- Опыт за бой (стартовые значения): победа — 100, ничья — 60, поражение — 40; сдача и технический проигрыш — 0.
- `expNeeded(level) = level * 500` — опыт для перехода с `level` на `level + 1`.
- Максимальный уровень: 30.
- Старт: уровень 1, все статы = 1, **стартовую расу выбирает игрок**, её навык = 3.
- За каждый уровень: +1 очко статов (attack / defense / power / knowledge, на выбор игрока).
- Каждый 3-й уровень: +1 очко навыка рас на выбор игрока; навыки разных рас можно качать **параллельно**, максимум навыка — 9.
- Прокачка открывает новые юниты (§4.2) и заклинания (§5.7), увеличивает лимит веса и удешевляет юниты прокачанных рас.
- Распределение очков — только через `allocatePoint`; порядок записывается в `statHistory` / `raceSkillHistory` (нужно для балансировки, §8).

### 11.2 Перераспределение очков

- Сбрасывает все распределённые очки статов и навыков рас (кроме стартовых 3 очков стартовой расы) в нераспределённые.
- **Бесплатно — один раз за сезон** (8 недель, `lastFreeRespecSeason`).
- Сверх этого — за **зелье перераспределения** (покупка, §12.3).
- Во время поиска матча или боя недоступно.

## 12. Монетизация

**Ключевой принцип: донат не даёт боевого преимущества.**

### 12.1 Покупка опыта (XP Boost)

- Пакеты: «×2 опыта на N рейтинговых боёв» и разовые пакеты опыта.
- Купленный опыт ускоряет прогрессию, но не даёт преимущества в бою: матчмейкинг ограничивает разницу уровней (§7.3), а бой проходит на уровне слабейшего (§8).
- Опыт за ботов по-прежнему не начисляется.

### 12.2 Скины

| Тип | Описание |
|---|---|
| **Персональный скин на заказ** | Уникальный арт для конкретного юнита по заявке игрока; создаётся ИИ (позже — художником), утверждается владельцем продукта; только у этого игрока |
| **Общие нестандартные скины** | Тематические пакеты (праздничные, альтернативные расцветки), доступны всем покупателям |
| **Анимации юнитов** | Альтернативные анимации победы/смерти |
| **Аватары и рамки профиля** | Косметика в профиле и лобби |

Требования к скинам (чтобы не давать преимущества):
- Сохраняются силуэт, размер, читаемость типа юнита и его анимаций атаки.
- Скин не может маскировать юнит под другой; в тултипе и очереди всегда виден реальный тип.
- Персональные скины проходят модерацию владельцем продукта перед выдачей.
- Скины хранятся в Firebase Storage, принадлежность — в `/entitlements/{uid}`.
- По умолчанию скин виден **всем** участникам боя. Настройка **«Показывать соперников в стандартных скинах»** отключает чужие скины локально у игрока, который её включил.
- Система тегов для фильтрации скинов в магазине.

Флоу персонального скина: заявка игрока (юнит + описание) → оплата → генерация вариантов → модерация → выдача; при отклонении модерацией — возврат средств.

### 12.3 Прочие механики монетизации

- **Battle Pass** — сезонный пропуск с косметическими наградами за рейтинговые PvP-бои (бесплатная и премиум-ветки).
- **Зелье перераспределения** — внеочередной сброс очков героя (§11.2). Не даёт преимущества: доступный набор очков не меняется, бесплатный сброс есть раз в сезон.
- **Смена имени** — разовая платная операция.
- **Дополнительные слоты пресетов армии** — не влияет на лимит веса.

Приоритета в очереди за деньги нет.

### 12.4 Ценовые ориентиры

Принцип: массовые покупки — недорогие, дорогие — только уникальные персональные скины. Цены ниже — ориентиры для ценовых сеток магазинов, окончательные определяются перед этапом 5.

| Товар | Ориентир |
|---|---|
| XP Boost, зелье перераспределения, слот пресета, смена имени | $0.99–1.99 |
| Общий скин юнита | $1.99–2.99 |
| Тематический пакет скинов | $4.99 |
| Battle Pass (премиум, сезон) | $4.99 |
| Персональный скин на заказ | от $29.99 |

### 12.5 Платежи

- iOS / Android: только встроенные покупки магазинов (требование App Store и Google Play для цифровых товаров) через **RevenueCat**.
- Web: **Stripe** (или RevenueCat Web Billing).
- Аккаунты разработчика (App Store, Google Play, Stripe, Firebase/Google Cloud) оформляет владелец продукта на себя.
- Покупки подтверждаются серверно: вебхук → `paymentsWebhook` → `/entitlements/{uid}`. Клиент покупки не записывает.
- Цены — по региональным ценовым сеткам магазинов; в регионах, где оплата недоступна, магазин показывается в режиме «только просмотр», игра полностью доступна.

### 12.6 Что запрещено продавать

- Дополнительный вес армии.
- Бонусы к статам в бою.
- Заклинания или способности юнитов.
- Влияние на рейтинг и на условия и скорость матчмейкинга.

## 13. Аналитика и баланс

- По окончании каждого боя `finishBattle` пишет `/battleStats/{battleId}`: режим, `battleLevel`, `balanceVersion`, составы армий (после урезания), использованные заклинания, итог, длительность, нанесённый/полученный урон по юнитам.
- Данные экспортируются в BigQuery. Метрики для балансировки:
  - win rate и pick rate по юнитам, расам и заклинаниям;
  - доля побед первой ходящей стороны;
  - доля боёв, закончившихся по лимиту раундов;
  - время ожидания матча и доля ушедших в бой с ботом.
- Игровые данные (юниты, заклинания, константы) лежат в `game-core` и версионируются (`balanceVersion`). Изменение баланса — релиз `game-core` в Cloud Functions и клиенте; клиент с устаревшей версией получает требование обновиться перед PvP.

## 15. Очерёдность разработки

Разработку пробной версии выполняет ИИ; каждый этап завершается проверкой в Docker (§15.1) и ревью владельцем продукта. Оценок в неделях нет — порядок определяется зависимостями.

### 15.1 Проверка в Docker после каждого этапа

После каждого крупного этапа (и перед ревью владельцем) выполняется **полная регрессионная проверка всего готового функционала**, а не только нового.

- **Окружение** — `docker compose` в репозитории, поднимается одной командой:
  - Firebase Emulator Suite (Auth, Firestore, Realtime Database, Functions, Storage) с тестовыми данными (seed);
  - собранный web-клиент (Expo for Web) против эмуляторов;
  - контейнер-раннер тестов.
- **Состав проверки**:
  - юнит-тесты `game-core` и `functions` (Vitest);
  - тесты Security Rules в эмуляторе;
  - интеграционные тесты Cloud Functions (матчмейкинг, ходы, таймеры, балансировка, платежи через тестовые вебхуки);
  - e2e-сценарии web-клиента (Playwright): каждый готовый пользовательский сценарий, например «гость → бой с ботом», «два игрока → матч 1v1 → бой до конца»;
  - проверка сборки мобильных клиентов (`expo export` / сборка без публикации).
- **Правила**:
  - этап не считается завершённым, пока вся проверка не проходит;
  - найденная регрессия исправляется до перехода к следующему этапу;
  - e2e-сценарии нового этапа добавляются в общий набор и дальше проверяются на всех последующих этапах;
  - итог проверки (что прогнано, результаты, известные ограничения) прикладывается к ревью владельцу продукта.
- Тот же набор запускается в CI (GitHub Actions) на каждый push.

## 16. Ключевые риски

| Риск | Митигация |
|---|---|
| Читерство (подмена ходов, предсказание бросков) | Клиент не пишет в бой; CF валидирует каждый ход; состояние PRNG скрыто |
| Десинхронизация в командных боях | Единый источник правды — документ боя в Firestore; `seq` отбрасывает устаревшие действия |
| Зависшие бои (AFK, обрыв связи) | Таймер хода, авто-Defend, технический проигрыш |
| Низкий онлайн и долгое ожидание из-за ограничения уровней | Боты как основной контент на старте; мониторинг времени ожидания; при необходимости — пересмотр `MAX_LEVEL_GAP` |
| Дисбаланс стартовых характеристик | Сбор статистики с первого PvP-боя (§13); версионирование баланса |
| Объём графики: 112 юнитов + скины | Эталонная раса → остальные по шаблону; альтернативные юниты частично переиспользуют элементы базовых |
| Токсичность в чате без фильтра | Жалобы со снимком чата, персональный чёрный список, ручной бан |
| Качество и единообразие графики, созданной ИИ | Единый стилевой гайд, ревью каждой расы владельцем; ассеты заменяемы без изменений кода |
| Авторские права и торговые марки (heroeswm.ru, Heroes of Might and Magic) | Только как референс; собственные изображения и имена (§4.1, §10.1) |
| Производительность Skia на слабых устройствах / web | Упрощённые спрайты при FPS < 30; ленивая загрузка CanvasKit на web |
| Стоимость Firestore | Один документ боя + события; подписка только на активный бой |
| Отклонение в App Store / Google Play | Только IAP для цифровых товаров; Sign in with Apple; удаление аккаунта из приложения |
| Недоступность оплаты в отдельных регионах | Игра полностью доступна без покупок; магазин в режиме просмотра |
| Балансировка воспринимается как несправедливость | Явно показывать уровень боя и урезание армии в UI |
